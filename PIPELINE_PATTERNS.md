# Схемы взаимодействия модулей (Pipeline Patterns)

## Концепция Pipeline

Pipeline (конвейер) - это последовательность или граф модулей, где выход одного модуля передаётся на вход следующего. Система поддерживает различные паттерны соединения модулей.

---

## БАЗОВЫЕ ПАТТЕРНЫ

### 1. Линейный конвейер (Sequential Pipeline)

Простейший паттерн: модули выполняются последовательно один за другим.

```
┌────────┐    ┌────────┐    ┌────────┐    ┌────────┐
│Модуль 1│ => │Модуль 2│ => │Модуль 3│ => │Модуль 4│
└────────┘    └────────┘    └────────┘    └────────┘
```

**Пример: Обработка текста**
```
[Загрузка TXT] => [Очистка текста] => [Извлечение email] => [Экспорт CSV]
```

**Описание в JSON**:
```json
{
  "pipeline_type": "sequential",
  "modules": [
    {"id": "load_txt", "order": 1},
    {"id": "clean_text", "order": 2},
    {"id": "extract_email", "order": 3},
    {"id": "export_csv", "order": 4}
  ]
}
```

---

### 2. Ветвление (Fork/Fan-out)

Один модуль передаёт данные в несколько разных модулей параллельно.

```
                    ┌────────┐
                 => │Модуль 2│
                 │  └────────┘
┌────────┐       │
│Модуль 1│ ====> ├─ ┌────────┐
└────────┘       │  │Модуль 3│
                 │  └────────┘
                 └─ ┌────────┐
                    │Модуль 4│
                    └────────┘
```

**Пример: Множественный экспорт**
```
                    => [Экспорт JSON]
                    │
[Обработка данных]  => [Экспорт CSV]
                    │
                    => [Отправка на email]
```

**Описание в JSON**:
```json
{
  "pipeline_type": "fork",
  "source": {"id": "process_data"},
  "targets": [
    {"id": "export_json"},
    {"id": "export_csv"},
    {"id": "send_email"}
  ],
  "execution": "parallel"
}
```

---

### 3. Слияние (Join/Fan-in)

Несколько модулей передают данные в один общий модуль.

```
┌────────┐  │
│Модуль 1│ =>│
└────────┘  │
            │   ┌────────┐
┌────────┐  ├=> │Модуль 4│
│Модуль 2│ =>│  └────────┘
└────────┘  │
            │
┌────────┐  │
│Модуль 3│ =>│
└────────┘
```

**Пример: Объединение данных из разных источников**
```
[Загрузка CSV 1]  =>│
                    │=> [Слияние данных] => [Анализ]
[Загрузка CSV 2]  =>│
```

**Описание в JSON**:
```json
{
  "pipeline_type": "join",
  "sources": [
    {"id": "load_csv_1"},
    {"id": "load_csv_2"}
  ],
  "target": {"id": "merge_data"},
  "merge_strategy": "concat"
}
```

---

### 4. Условное ветвление (Conditional Routing)

Данные направляются в разные модули в зависимости от условий.

```
                    ┌────────┐
           если A → │Модуль 2│
                    └────────┘
┌────────┐
│Модуль 1│          ┌────────┐
│(роутер)│─если B → │Модуль 3│
└────────┘          └────────┘

           иначе  → ┌────────┐
                    │Модуль 4│
                    └────────┘
```

**Пример: Обработка по типу файла**
```
                    => [PDF обработка]      (если PDF)
[Определение типа]  => [Excel обработка]    (если XLS)
                    => [Текст обработка]    (иначе)
```

**Описание в JSON**:
```json
{
  "pipeline_type": "conditional",
  "router": {"id": "file_type_router"},
  "conditions": [
    {
      "condition": "file_type == 'pdf'",
      "target": {"id": "pdf_processor"}
    },
    {
      "condition": "file_type == 'excel'",
      "target": {"id": "excel_processor"}
    },
    {
      "condition": "default",
      "target": {"id": "text_processor"}
    }
  ]
}
```

---

### 5. Цикл (Loop)

Модуль обрабатывает коллекцию элементов, применяя один и тот же процесс к каждому.

```
┌──────────────────────────────┐
│  Для каждого элемента:       │
│                              │
│  ┌────────┐    ┌────────┐   │
│  │Модуль 2│ => │Модуль 3│   │
│  └────────┘    └────────┘   │
└──────────────────────────────┘
        │
        ↓
   ┌────────┐
   │Модуль 4│ (агрегация результатов)
   └────────┘
```

**Пример: Обработка пакета файлов**
```
┌─────────────────────────────────┐
│ Для каждого файла в архиве:     │
│ [Извлечь] => [Обработать]       │
└─────────────────────────────────┘
         │
         => [Объединить результаты]
```

**Описание в JSON**:
```json
{
  "pipeline_type": "loop",
  "iterator": {"id": "unzip_files"},
  "loop_body": [
    {"id": "extract_file"},
    {"id": "process_file"}
  ],
  "aggregator": {"id": "merge_results"}
}
```

---

### 6. Граф (DAG - Directed Acyclic Graph)

Сложная структура с множественными ветвлениями и слияниями.

```
        ┌────────┐
     => │Модуль 2│ =>┐
     │  └────────┘   │
┌────────┐           ├=> ┌────────┐
│Модуль 1│           │   │Модуль 5│ => [Выход]
└────────┘           │   └────────┘
     │  ┌────────┐   │
     => │Модуль 3│ =>┤
        └────────┘   │
             │       │
             ↓       │
        ┌────────┐   │
        │Модуль 4│ =>┘
        └────────┘
```

**Пример: Комплексная обработка данных**
```
        => [Фильтр А] =>┐
        │               │
[Ввод]  => [Фильтр Б] => [Слияние] => [Анализ] => [Отчёт]
        │               │
        => [Валидация] =>┘
```

## ПРОДВИНУТЫЕ ПАТТЕРНЫ

### 7. Map-Reduce

Распределённая обработка данных с последующей агрегацией.

```
                    ┌────────┐
                 => │Worker 1│ =>┐
                 │  └────────┘   │
┌──────┐         │  ┌────────┐   │   ┌────────┐
│Split │ ======> ├> │Worker 2│ =>├=> │Reduce  │
└──────┘         │  └────────┘   │   └────────┘
                 │  ┌────────┐   │
                 => │Worker 3│ =>┘
                    └────────┘
```

**Пример: Обработка большого датасета**
```
[Разбить на части] => [Обработка части 1] =>┐
                   => [Обработка части 2] =>├=> [Агрегация]
                   => [Обработка части 3] =>┘
```

---

### 8. Pipeline с кэшированием

Промежуточные результаты сохраняются для повторного использования.

```
┌────────┐    ┌────────┐💾   ┌────────┐💾   ┌────────┐
│Модуль 1│ => │Модуль 2│  => │Модуль 3│  => │Модуль 4│
└────────┘    └────────┘     └────────┘     └────────┘
                  ↑              ↑
              [Cache 1]      [Cache 2]
```

**Применение**: При повторных запусках используются закэшированные результаты.

---

### 9. Pipeline с обработкой ошибок

Каждый модуль имеет резервный путь при ошибке.

```
┌────────┐    ┌────────┐    ┌────────┐
│Модуль 1│ => │Модуль 2│ => │Модуль 3│
└────────┘    └────────┘    └────────┘
    │             │             │
    ↓ (error)     ↓ (error)     ↓ (error)
┌────────┐    ┌────────┐    ┌────────┐
│Retry 1 │    │Fallback│    │Log+Stop│
└────────┘    └────────┘    └────────┘
```

## ПРИМЕРЫ РЕАЛЬНЫХ СЦЕНАРИЕВ

### Сценарий 1: ETL процесс для бизнес-отчёта

```
┌─────────────────────────────────────────────┐
│ EXTRACT (Извлечение)                        │
├─────────────────────────────────────────────┤
│ [БД продажи] =>┐                            │
│ [БД клиенты] =>├=> [Слияние данных]         │
│ [Excel файл] =>┘                            │
└─────────────────────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────┐
│ TRANSFORM (Трансформация)                   │
├─────────────────────────────────────────────┤
│ [Очистка] => [Валидация] => [Обогащение]    │
│    => [Агрегация] => [Группировка]          │
└─────────────────────────────────────────────┘
                 ↓
┌─────────────────────────────────────────────┐
│ LOAD (Загрузка)                             │
├─────────────────────────────────────────────┤
│ [Визуализация] => [Генерация PDF]           │
│    => [Отправка на email]                   │
└─────────────────────────────────────────────┘
```

**Описание в JSON**:
```json
{
  "name": "Ежедневный отчёт о продажах",
  "schedule": "0 9 * * *",
  "stages": [
    {
      "name": "extract",
      "modules": [
        {"id": "db_sales", "type": "parallel"},
        {"id": "db_customers", "type": "parallel"},
        {"id": "excel_import", "type": "parallel"}
      ],
      "merge": {"id": "merge_sources"}
    },
    {
      "name": "transform",
      "modules": [
        {"id": "clean_data"},
        {"id": "validate_data"},
        {"id": "enrich_data"},
        {"id": "aggregate"},
        {"id": "group_by_category"}
      ]
    },
    {
      "name": "load",
      "modules": [
        {"id": "visualize"},
        {"id": "generate_pdf"},
        {"id": "send_email"}
      ]
    }
  ],
  "error_handling": "log_and_notify",
  "notifications": ["email", "slack"]
}
```

## BEST PRACTICES

### 1. Модульность
Создавайте небольшие, специализированные модули вместо монолитных.

### 2. Идемпотентность
Модули должны давать одинаковый результат при повторном запуске с теми же данными.

### 3. Обработка ошибок
Каждый модуль должен корректно обрабатывать ошибки и сообщать о них.

### 4. Логирование
Логируйте все важные операции для отладки и мониторинга.

### 5. Производительность
Используйте параллельное выполнение там, где это возможно.

### 6. Кэширование
Кэшируйте промежуточные результаты дорогостоящих операций.

### 7. Тестирование
Тестируйте каждый модуль отдельно и весь pipeline целиком.
